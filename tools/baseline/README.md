# Baseline corpus

Run `tools/baseline/verify.sh` from the repository root. The command downloads the pinned dyn4j 6.0.0 binary and sources JAR, checks their SHA-256 values, checks out source revision `058bf6d982a0fb89b54050f929f6ea9dae53b714`, and writes a complete declaration inventory and JUnit run summary.

The default cache is `.cache/baseline`. It contains upstream artifacts and generated test classes. The inventory and run summary are written to `docs/verification/baseline-inventory.json` and `docs/verification/baseline-run.json`. Keep those outputs with the commit that records the run.

Use `--candidate PATH` to compare a candidate JAR with the pinned baseline. The `compare` command and shared comparison function copy the baseline, candidate, and each dependency JAR to private snapshots. They check the baseline snapshot against its pinned SHA-256 before reading its API. Inventories, inherited-member lookup, and Java 8 fixture compilations use the snapshots. Reported JAR hashes identify the snapshot bytes; a changed snapshot fails the comparison. The comparator checks public and protected types, members, generic declarations, superclass contracts, access, and method modifiers. It accepts added interfaces, member order changes, wider access, and removal of method or type `final`. It accepts added method `final` only when the baseline class was already final. Added `final` on overridable or static methods in extensible classes remains incompatible. Field finality stays exact because removing it can break Java constant use. It accepts a constructor parameter widened from `List<T>` to `List<? extends T>`; it does not apply that rule to methods, where Java overrides can break. It skips compiler bridge and synthetic methods while keeping the source method. An interface inherited through another candidate interface or superclass satisfies the same source contract when its generic arguments match after type-variable substitution. An omitted explicit `extends Object` is equivalent to the implicit superclass. Exact accepted changes remain in `compatible_differences`; missing or incompatible contracts remain in `missing_types` and `signature_mismatches`.

The added-member gate checks baseline subclassable public, protected, and package-private types, inherited methods and fields, and same-package Java extensions. A newly declared `final` override remains a risk even when its source signature matches an inherited baseline method. An added field that hides an inherited constant remains a risk. Added overloads on final types can make old calls ambiguous; the gate accepts only disjoint fixed-arity instance overloads there. Added public fields and static methods remain risks even on final types because wildcard imports can become ambiguous. New source-visible risks appear in `added_member_risks`, with candidate and declaring types, descriptor, class-file flags, origin, and candidate SHA-256. Missing package-private subclassable types and unreadable inventories appear in `inventory_errors`. Class-file `EnclosingMethod` evidence excludes anonymous and local classes; `package-info` is not a source type. The `InnerClasses` access flags identify private nested types even when the plain `javap` header omits `private`; real package-private types stay in scope. Private, bridge, and `ACC_SYNTHETIC` helpers are excluded only after their class-file flags are read. Methods with a hyphen in the JVM name cannot be named by Java source and are excluded from the added-member source gate; Java-identifier additions such as `Companion` fields and `getEntries` methods remain risks. Pass `--dependency-jar PATH` for a required class on the candidate's compile classpath; its hash is recorded.

Pass `--require-fixture` with all three unchanged Java 8 sources in `tools/baseline/fixtures/`. The command copies each source to a private snapshot, hashes that copy, and compiles the same copy against both providers. It checks the snapshot hash again after compilation and matches the pinned source hashes against those compiled bytes. An unrelated compiling file does not satisfy the required set. Missing, changed, empty, or baseline-invalid fixtures fail as `fixture_errors`; candidate compile failures appear in `fixture_failures`. The source gate does not prove runtime dispatch: a synthetic final method can still cause `IncompatibleClassChangeError` when loading a subclass compiled against the baseline. The gate also cannot enumerate every possible consumer source context, including external overloads and imports; compile the actual unchanged consumers before claiming complete source compatibility. Use `python3 tools/baseline/verify.py compare --baseline-jar BASELINE --candidate CANDIDATE --only TYPE` to inspect selected types. A selected comparison does not qualify a full JAR.

Use `--inventory-only` to refresh the inventory without running tests. Run `tools/baseline/verify.sh --help` for path overrides.

`scripts/verify-foundation-jvm-api.py` applies the same source checks to 13 foundation types, including package-visible members used by Java source in `org.dyn4j` packages.

The required-declaration count in the default full comparison covers public and protected types. The added-member gate also checks package-private subclassable types. The separate geometry slice wrapper still reports required declarations only; use the shared `compare` command to inspect its added-member risks.

The JAR is the production dependency for the oracle only. The runner compiles the unchanged upstream tests with JUnit 4.13.1 and Hamcrest 1.3, then executes test classes in one JUnit process. It includes `src/test/resources`. `javac --release 8` limits the harness and tests to Java 8 APIs and bytecode. The report records compiler and runtime versions, harness bytecode version, dependency hashes, and each test input hash. No upstream source is changed.

The verifier rejects changed, untracked, or ignored source inputs before checkout. Git operations on the checkout ignore local replacement refs, bind the requested worktree, and remove inherited `GIT_*` settings that can redirect repository data. Clone uses the same environment rule; fetch and clone retain network authentication settings. The verifier reads every tracked production and test Java file as a regular file from that checkout and compares its actual bytes with the original pinned Git object. It repeats that check before a clean source, inventory, or JUnit result is returned. This catches changes hidden by index flags and changes during a run; Git status still detects untracked and ignored inputs. It checks every production Java entry in a private sources JAR snapshot against the pinned Git revision. The baseline inventory reads a pinned binary snapshot and records source hashes and `@Test` counts from the checked bytes. The JUnit runner copies test sources, resources, and dependency JARs to private inputs and hashes the bytes it compiles or runs. Each path checks its snapshots again before reporting. The verifier leaves a dirty checkout in place and reports the problem. The suite must run exactly 2,385 cases with no failures or ignored cases. `check-run --report PATH` checks a saved run report.

`test_annotations` is a source inventory value. `actual_executed_cases` comes from JUnit's run count and can differ because parameterized tests expand and runners can add or ignore cases. This corpus establishes the fixed oracle; it does not qualify dyn4k numerical parity or physical behavior.

The upstream license text is retained in `tools/baseline/UPSTREAM-LICENSE.md`. The tool does not edit upstream files.

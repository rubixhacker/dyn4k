# Numerical and migration acceptance recommendation

**Reader and action.** This is for the dyn4k spec owner and implementation team. Freeze the decisions below in the published spec and issue tracker, then start the full dyn4j 6.0.0 port. Track every unexecuted check as **unpassed**. This document recommends policy and limits; it does not report a port test, a target runtime test, a migrated application run, or release qualification. The current user authorization covers the remaining recommendations, spec and issue publication, and implementation. This subtask only prepares this handoff document.

## Fixed contract and comparison rules

1. Port the complete pinned [dyn4j source at `058bf6d982a0fb89b54050f929f6ea9dae53b714`](https://github.com/dyn4j/dyn4j/tree/058bf6d982a0fb89b54050f929f6ea9dae53b714), matching the 6.0.0 binary JAR SHA-256 `204ca8dd55626ad3727b82dacb37df1800c5eff0d6bb6e782b6e5af5162b2b3e`. Use one authoritative mutable Kotlin model for the Kotlin API and fixed-version compatibility shim. Preserve the full charter scope, including all non-deprecated experimental targets, baseline algorithms, double precision, and source compatibility for unchanged Java code. Preserve the pinned [license](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/LICENSE.md) verbatim in distributions; retain source notices. [Baseline inventory](https://github.com/rubixhacker/dyn4k/blob/2925a86d2b9bcdbc512f71b476ec00f02509e8b0/docs/research/baseline.md); [approved artifact contract](https://github.com/rubixhacker/dyn4k/issues/9#issuecomment-6160753104).
2. Preserve observable baseline behavior, including bugs, unless an individual exception is documented, approved, and covered by a regression fixture. Both APIs must use the same physics behavior. Use exact checks for discrete outcomes, event and callback order, exceptions, copy/class/filter semantics, identity, aliasing, mutation, and collection views. A numeric difference that changes a discrete outcome fails pending investigation. [Approved policy](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-5651895320); [two-layer rule](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-5651896947).
3. For every numerical fixture, freeze inputs, units, scale, duration, actions, source/artifact hashes, reference hashes, checkpoints, metric, absolute limit, and relative limit before using it for acceptance. Compare each scalar as `abs(port - reference) <= absoluteLimit + relativeLimit * abs(reference)`; compare vector components separately unless a named fixture rule says otherwise. Use shortest directed angle only for orientation/direction, and direct unwrapped difference for accumulated rotation. Every required sample and every callback must pass; an average or percentile cannot hide a failure. Unexpected nonfinite values fail. Apply one fixture budget across all supported targets, runtimes, and build configurations. No automatic widening or target-specific exception follows a failure. [Approved comparison rule](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-5651923228); [shared-limit rule](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-5652133613); [freeze rule](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-5652055878).

## Sleep/wake: two distinct profiles

**Default profile.** Keep the original 30/60/120 Hz references and their approved phase schedules. They are behavioral and numerical parity references, and they retain the approved six-group exact consistency checks. Their represented-geometry physical penetration gate **failed in 125,847 of 126,000 end states**. The failure includes every resting sample. Do not call that gate passed, transfer a configured-profile pass to it, replace its reference, or enlarge its approved ceilings. Continue to report the default physical gate as failed unless a later, separately approved compatibility/quality decision changes its disposition. [Frozen phases](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-6171650674); [failed exact audit](https://github.com/rubixhacker/dyn4k/blob/b7af287c3581f402053511d9556d65e610d71a5e/docs/research/sleep-wake-penetration-acceptance.md).

**Configured physical-quality profile.** Select the exact repetition-1 references at outer 30/60/120 Hz; retain repetition 2 as corroboration. Internal `h = 1/120 s`, outer grouping `4/2/1`, `linearTolerance = 1/4096 m`, and at most eight position iterations are binding. The [manifest at `a7718eb6380b8fc51179a953dff4f3f33949c801`](https://github.com/rubixhacker/dyn4k/blob/a7718eb6380b8fc51179a953dff4f3f33949c801/docs/research/sleep-wake-quality-candidate-manifest.json) has SHA-256 `7efd60aa76cab10fdc27eb8e968a2868e854433cc4556e10257dbd290a63e554`; the raw archive SHA-256 is `057d96767dcf4ef863afb61417f8ef9cc6b7fc1442e0e39df55bbe006cb1212c`. Evaluate the already approved phase ceilings: initial approach `0 m`, impact `0.010 m`, initial and wake settling `0.005 m`, rest before/after wake `0.001 m`, using the deepest transformed square vertex below the floor. The frozen baseline passed all **432,000 internal states** and **252,000 endpoint mappings** with zero failures. The six-group exact same-run checks also passed all six captures; endpoints are copies and never advance simulation or recorder state. These are stored binary64 represented-geometry and consistency findings, not native 30/60 Hz quality or port/runtime proof. [Selection](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-6174366120); [penetration audit](https://github.com/rubixhacker/dyn4k/blob/164dc39eb086ac202fdffa8a493915c216bc1be0/docs/research/sleep-wake-quality-acceptance.md); [exact consistency audit](https://github.com/rubixhacker/dyn4k/blob/44dd7cf05502fa4b5fdc3523e3271c3cba335de8/docs/research/sleep-wake-quality-exact-checks.md).

**Configured-profile parity limits already approved** (zero relative allowance; compare every matching internal checkpoint and callback stage):

| Recorded quantity | Maximum absolute difference and metric |
| --- | --- |

Sleeping/floor/immediate-action zeros, body/contact identities, event sequence, phase-correct previous-transform copies, and the approved six-group package remain exact. Parity allowance never increases a physical penetration ceiling.

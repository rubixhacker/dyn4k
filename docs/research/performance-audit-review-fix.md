# Audited staged JVM performance archive

The [performance manifest task](https://github.com/rubixhacker/dyn4k/issues/17) remains open. This report addresses the independent audit findings while retaining the one-world measurement sequence. The [version 1](performance-candidate-v1/) and [version 2](performance-candidate-v2/) archives remain as historical evidence. Version 1 used a reachable warm world during measurement. Version 2 repaired that lifetime, but did not preserve the raw retained-heap marker or bind every audit input to resolvable source and artifacts. The current verifier reports version 2 as unavailable, with a nonzero exit code. No approved budget, target, runtime row, fixture, or sustained-run requirement changed.

The verifier now resolves that exact Git commit and its two engine trees. It compares seven recorded source files against their committed bytes and current files. It resolves both candidate classpaths from the local staged Maven coordinates, then hashes every present classpath entry and the staged JVM JARs. It also checks the recorded Java executable, version, flags, and route entry points. A missing commit, substituted source path, changed artifact hash, or unavailable file prevents a successful audit. This is a local source and binary identity check; it is not a reproducible-build attestation.

The staged core JVM JAR SHA-256 is `b56d947ea183e6b8e7affddd1f24ad3ebd8e3276c6c56fa3e319e114793165f4`. The staged Kotlin JVM JAR is `7e32875e21cac6bf1dfdc09627f0db2b31211c706054865db6d24dc5ef638647`. The same six [negative controls](performance-candidate-v3/negative-controls/negative-controls.json) rejected missing and crossed routes, upstream and altered candidate JARs, and empty and inactive scenes.

Every measured step process now preserves the complete stderr stream as a separately hashed raw file. The verifier parses its construction, process, route, retained-heap, and collection markers. It compares them with the indexed values and the cleaned warm-up CSV. Every plateau process also preserves its original stderr stream and route markers. Each group records SHA-256 hashes for the committed `measure.py` and `candidate_pilot.py` capture tools. The verifier checks their bytes against the recorded commit and current files. It validates every required timing, allocation, memory, activity, and plateau channel, including permitted `-1` sentinels. It rejects negative mutation and lateness times, invalid allocation sentinels, negative heap or RSS samples, invalid counters, and absent or non-increasing plateau collection counts. The retained-heap marker cannot be changed in either the index or hashed raw stream without rejection.

## Raw observations and uncertainty

All 45 required bounded processes completed with zero capture failures: 36 two-second timing/allocation pilots, three 30-second timing runs, three two-second memory runs, and three 100-cycle plateau runs. Each short process warmed for 60 steps and measured 120 steps at 60 Hz. Each longer timing process warmed and measured 1,800 steps. Every required process has a hashed raw stderr file. The [short pilot index](performance-candidate-v3/pilot/evidence.json), [noise index](performance-candidate-v3/noise/evidence.json), [memory index](performance-candidate-v3/memory/evidence.json), and [plateau index](performance-candidate-v3/plateau/evidence.json) contain every raw measured and warm-up CSV digest, process ID, workload ID, and step or cycle count.

For small separated motion, short timing median/p99 step times were 133,623/312,231 ns baseline, 124,276/333,382 ns direct Kotlin, and 153,871/447,368 ns compatibility. The 30-second timing median/p99 values were 110,439/219,947 ns baseline, 94,570/240,966 ns direct, and 79,621/198,596 ns compatibility. The [analysis index](performance-candidate-v3/analysis.json) retains 2,000 paired one-second block resamples as exploratory uncertainty. Host-noise point readings included load averages of `14.71 20.93 21.88` during capture and `8.48 13.73 18.46` after capture. These are not continuous telemetry. Warm-up convergence and a quiet host window remain unvalidated. No ratio or budget decision follows from these values.

The three memory processes each recorded one collection with the measured world alive. The raw stderr SHA-256 values are `8ef5d3276d3bda2fa1fef3d8e544e5f71be06ed3169e96c950b81da600bf25e9` baseline, `76237df2341c73e9f50f20f28291145f7d7576bb004857824b84d39376392148` direct, and `be11f79d5bbcf3c0b9fbbfde415e4846f669efa0bb208989f68d5988d9f39db4` compatibility. Recomputed post-collection live-heap readings were 2,174,416, 2,327,528, and 2,281,880 bytes. Peak process-RSS deltas were 24,956,928, 31,989,760, and 32,817,152 bytes. These process readings do not attribute managed, native, or reserved memory to the workload. The 16 MiB workload cap remains unpassed.

The 100-cycle absolute median live-heap drifts were 0.292% baseline, 0.084% direct, and 0.268% compatibility. Their per-cycle collection counters increased on every indexed cycle. This is a bounded plateau observation. Direct and compatibility CCD state traces still require numerical and event-order investigation; these pilots do not qualify that comparison.

The version 3 evidence-index SHA-256 values are `8cbe44d6e61539870473d028b53c62fdb3af7ced1c8e6f42b65c34de918566a9` pilot, `ad99ec375d94f53b94b6016e3edc8d640d79a0ccca24f02ca99f97d08697a6f0` noise, `b6ca5f9f7f8476c40de7e99eecfcca711cebfebdb440c3d47bba06f3471b848f` memory, and `381dd7ca4bd9552a9ea895f8b380b8537ee5a6902d99a7ed69dbe8530968f58a` plateau.

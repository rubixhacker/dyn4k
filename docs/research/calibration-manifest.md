# Draft numerical calibration manifest

Research for [Specify the concrete numerical calibration manifest](https://github.com/rubixhacker/dyn4k/issues/14), 2026-09-13. **Draft for live approval: no proposed input grid, new fixture, metric supplement, or numerical allowance below is approved or measured.** No engine implementation or simulation run occurred. The approved checkpoints in [Define numerical and migration acceptance](https://github.com/rubixhacker/dyn4k/issues/7) remain authoritative.

## Frozen evidence and notation

Baseline source: dyn4j `058bf6d982a0fb89b54050f929f6ea9dae53b714`, tag 6.0.0, checked out locally. Artifact integrity pins are in [the baseline report](baseline.md). The [earlier numerical inventory](numerical-calibration.md) documents observed assertion deltas; none becomes a port tolerance by inheritance.

**U** denotes an exact upstream seed: execute the named method's complete setup and ordered mutations, preserving all unspecified values from that source revision, including defaults. **P** denotes a proposed additional case. Do not approximate U by only the abbreviated values in these tables. A generated manifest must serialize the complete effective settings, fixture properties, transforms and action schedule before references can be frozen.

Approved: at least 600 simulated seconds for designated long runs; numerical capture after every physics step; every callback in order, including within a step; componentwise vectors; shortest difference for orientation; unwrapped accumulated rotation; one approved limit set per fixture across all target/runtime/build lanes; explicit reference regeneration review; baseline invariant discrepancies block adopting that invariant.

Proposed deterministic mode probes use the first compatible U setup per row, changing exactly the listed mode fields. Scalar candidate grids: ratios `{0.5,1,2}` (Angle additionally `−1` if accepted); damping ratio `{0,0.2,1}`; spring frequency `{2,8}` Hz; correction factor `{0,0.3,1}`; force caps `{0,10,1000}` N; torque caps `{0,0.25,10}` N·m; linear motor speeds `{−1,0,1}` m/s; angular motor speeds `{−π/2,0,π/2}` rad/s. Linear limits `{−1,1}` m and equal `{0,0}`; angular limits `{−π/6,π/6}` and equal `{0,0}`. Each applicable boolean receives isolated false/true cases and one false→true→false sequence before steps 201/401; moving target changes by `(0.5,0.5)` m or π/6 before step 201. Probe one field at a time from its U setup, then explicitly combine enabled spring+motor+limits for Prismatic/Wheel, spring+limits for Distance/Weld, and motor+limits for Revolute. This is a proposed bounded interaction suite, not exhaustive Cartesian coverage. Zero values rejected by setters are recorded as API cases; they do not count as dynamic coverage. Before reference capture, expand this recipe into named rows with exact resolved values; a mode with no activated constraint or cap remains an uncovered gate.

## Dimensional scaling and translation proposal

Proposed exploratory scale multipliers `s={0.01,1,100}` and fixed world offsets in metres `O={(0,0),(1000,1000),(−1000,1000),(1000000,−1000000),(−1000000,1000000)}`. Apply the 15 combinations to G-circle/G-boundary, F-integrator world cases, C-bounce/C-stack/C-slide, CCD-world, L-spring and J-all's U fixedDistance and Revolute motor-with-limits representatives. Other joint modes remain nominal initially; this does not waive their full target execution. These grids test candidate magnitudes; no point is a support guarantee. Keep rejected or unstable points in the report for review.

Use `x′=O+s*x`, fixed time unit and **constant areal density**. The dimensional consequences below are derived proposals, supported by the baseline's kg/m² density definition, not measured similarity claims:

| Quantity | Multiplier / action |
| --- | --- |
| Shape lengths, body-relative positions, joint lengths and linear targets, linear limit distances | s; world points additionally receive O, body-local vectors do not |
| Mass, inertia | s² and s⁴ respectively; recompute from scaled shapes/density, preserving static/infinite mass semantics |
| Linear velocity, gravity/linear acceleration, restitution-speed threshold | s |
| Force, linear impulse, linear motor/spring force caps | s³ |
| Torque, angular impulse, angular motor/spring torque caps, energy | s⁴ |
| Linear spring stiffness and damping coefficient | s²; angular spring stiffness/damping coefficient s⁴ |
| Angles, angular velocity, angular limits, ratios, friction, restitution, damping ratio, spring frequency, body damping rates, timestep/horizon, iteration counts | unchanged |
| Linear solver tolerance, maximum linear correction/translation, warm-start distance, rest linear-velocity threshold | s; minimum rest time and angular tolerances/correction/rotation unchanged |
| Explicit broadphase expansion or configurable detector distance epsilon | scale by its dimension where exposed, record exact configuration; dimensionless values unchanged |

Inventory dimensional solver settings from [Settings](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/Settings.java#L38-L103). Internal fixed constants and rounding mean mathematical similarity is not automatically implementation similarity. Do not patch upstream epsilon constants for these runs. Compare baseline and port using identical scaled inputs; compare scaled/translated baseline runs to nominal separately as metamorphic diagnostics. Translate world anchors, pin targets and world query points consistently; do not translate vectors, forces, local anchors or a motor's relative target merely because its type is Vector2.

## Observables, metrics and world-position masking

Every step captures stable body/joint/fixture IDs; transforms; world centre and velocities; orientation; independently accumulated rotation where valid; rest flags; force/torque; joint anchors/lengths/angles, reactions, configured/effective modes; contact IDs, normal/tangent impulses and manifold geometry; CCD results. Each callback carries step index plus monotonically ordered within-step event index. Identity is assigned by fixture construction order, never pointer address. Exact discrete checks are separate from numerical fields.

Use the approved scalar formula for every scalar/vector component. Record orientation error as the shortest signed angular difference with an explicitly fixed wrap convention; accumulated rotation uses the unwrapped scalar value. A proposed instrumentation accumulator sums shortest orientation increments only when per-step rotation is strictly below π and there are no unrecorded transform mutations; otherwise expose/track the actual rotation updates or mark the observable unavailable. Do not pretend a wrapped orientation API measures total revolutions.

**Masking risk:** with an illustrative relative limit 1e−6 and baseline world coordinate 1e6 m, the relative term alone permits 1 m error. That is a mathematical example, not a proposed limit. The approved formula therefore needs a proposed supplemental frame-local measurement to make translation probes useful: capture `q=x−O` for both runs using the same immutable manifest origin O, and apply the same scalar formula componentwise to q with its own approved quantity limits. Also capture joint separation/contact gap for local geometry. Retain global-coordinate checks; never recenter each run on its current body position, which could erase real drift. Subtraction can itself lose low bits at large O, so record that limitation and inspect baseline representability before claiming supported magnitudes. This supplement requires explicit human approval.

For momentum and energy, record deviation from initial state each step and baseline parity separately; the numerical bounds remain unset. Angular momentum requires a fixed documented origin. Baseline invariant failure blocks adoption until the physics model, bound or baseline bug is resolved. Nonempty contacts and active constraint/cap evidence are coverage gates, not numerical pass substitutes.

## Required measurements and approval handoff

Before numerical limits can be proposed: expand the recipes into complete immutable inputs, run the baseline repeatedly with environment/artifact hashes, retain full-precision per-step outputs and ordered events, verify exercised modes, quantify baseline analytic/invariant residuals and scale/offset sensitivity, and diagnose rejected/unstable scenarios. Capture first failure with quantity, reference, actual and error; never average failures away. References need explicit review before any regeneration. Future port runs then use these same inputs on every approved lane and one shared limit set per fixture.

This draft supplies reviewable inputs and mode accounting, not empirical calibration or a finished acceptance contract. Human approval remains required for the proposed fixture/grid details, frame-local supplement, expansion into exact mode cases, invariant definitions/bounds and ultimately every absolute/relative limit. No concrete limit is offered without measurements.

Runnable-manifest gaps: P joint recipes still require explicit per-mode starting-state selection, numeric effective stiffness, stimulus capable of reaching each limit/cap, and resolved input snapshots. Detector-specific tolerances/broadphase settings need a dimensional inventory beyond Settings. Triangle predicate API selection and callback payload schemas need explicit bindings. These are named preparation tasks; the draft is not represented as immediately executable or exhaustive member-level coverage.

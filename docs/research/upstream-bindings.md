# Exact upstream calibration bindings

Pinned source: dyn4j `058bf6d982a0fb89b54050f929f6ea9dae53b714` (6.0.0).

`calibration/scripts/prepare-upstream.sh` checks the source revision, copies the upstream test tree into generated storage, and instruments the copies. Original files are never modified. Test bodies, assertions, setup methods, package access, and ordered mutations remain in their original classes. The generated source tree must not be treated as a maintained fork. Reproduce it using the script and pinned checkout.

`UpstreamCases` explicitly names the 40 required methods: two circle queries, two direct integrator methods, two timed-force/torque methods, two conservative advancement methods, and all 32 methods across ten joint simulation classes. Each method receives a fresh test instance and its original `setup` method where present. A failed original assertion is recorded and fails the run.

Instrumentation intercepts `w.step(n)` and forwards the unchanged count/timestep into `Capture.run`, which captures each individual physics step. Direct integration records immediately before and after each invocation; SAT/GJK and TOI wrappers record arguments before the original query and output afterward. Timed-force/torque completion records include elapsed time, accumulated time, and the original completion predicate. Query arguments retain original order and query calls are not duplicated. Circle methods do not request distance/witness points; TOI includes separation and the interpolated transform.

The 30 dimensional representatives in `UpstreamScaleCases` are generated from the original fixed-distance and motor-with/without-limits bodies. Shapes, positions, correction distance, distance target and both fixture restitution-velocity thresholds scale by s; static origin receives O; torque cap scales by s^4. The shared dimensional settings/detector routine is applied before original overrides. Numeric assertions retain their upstream deltas with distance/force/torque outputs normalized by their dimension. The original pre-step exact-distance assertion remains exact and emits an explicit PASS/FAIL observation. Only its `AssertionFailedError` is caught, solely to continue exploratory physics; a failed exact assertion remains a failure. Nominal U assertions are unchanged.

## Verification

An isolated physics smoke run against the pinned binary passed every original assertion in all 40 nominal methods: 816 world physics steps. The original scaled smoke executed another 1,440 steps, but incorrectly introduced a 1e-5 delta into the exact initial-distance assertion. That was a harness error, not an upstream or approved port tolerance; its earlier green result does not establish assertion fidelity. The initial captures also retained the default fixture restitution-velocity threshold instead of dimensionally scaling it.

Supplemental correction evidence is retained under `calibration/results/corrected-scale-exact`, `corrected-scale-a`, and `corrected-scale-b`. The exact-only correction produced all 75 physics gzip traces byte-identical to both original final runs. The two fully corrected runs each execute 30 representatives, 75 segments and 1,440 steps with scaled fixture thresholds; all 75 gzip traces, summaries and exact-assertion queries are byte-identical between those two runs. Compared to the retained original traces, every line after the input header is byte-identical. Each corrected input header differs only in the two fixture restitution-velocity thresholds. No original capture was overwritten.

Each corrected run records 11 PASS and four FAIL exact initial-distance checks. All failures occur at s=0.01 with nonzero offsets: normalized distance is 1.999999999998181 at (+1000,+1000) and (-1000,+1000), and 2.000000001862645 at (+1000000,-1000000) and (-1000000,+1000000), against exact expected 2.0. Other normalized assertions are unchanged and did not fail. These four failures are retained representability observations, not accepted errors. No numerical allowance or reference freeze follows from the corrections.

The remaining dimensional inventory of these two representatives was checked: constant density/recomputed mass and inertia, shape dimensions, body and anchor positions, distance target, motor torque cap, shared linear settings and detector parameters are scaled; gravity is exactly zero, and angular quantities and timesteps stay unchanged. No further exposed dimensional omission was identified in these two probes. Joint-connected collisions are disabled in their upstream setup, and the unchanged post-header records show the restitution-threshold correction did not affect these observed trajectories.

Compiler dependency: JUnit 4.13.2 (`junit:junit:4.13.2`). Source path must include both `calibration/generated` and `calibration/src`. Explicitly compile generated `org/dyn4j/simulation/*.java`, `collision/shapes/CircleCircleTest.java`, `collision/continuous/ConservativeAdvancementTest.java`, and `dynamics/AbstractPhysicsBodyTest.java`; javac resolves helper test classes through the source path. Runtime reflection alone does not make javac compile those classes.

## Limits requiring integrated review

The source is the full action schedule; snapshots immediately before each step segment capture the effective mutation results. Simple body, fixture, joint and world setter/translation/impulse statements additionally emit ordered source-action text immediately before execution; chained settings getters and complex statements remain represented by the original source plus segment input snapshots. Query/free-body records rely on Capture serializing the objects immediately, not retaining mutable references. Public getter serialization must be reviewed for complete fixture shape/transform, detector settings and body state; string-only object serialization is insufficient for immutable reference inputs. Scale diagnostics are supplementary and do not replace exact nominal methods.

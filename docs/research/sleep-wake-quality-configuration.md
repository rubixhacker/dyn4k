# Separately configured sleep/wake qualification: proposal and limitation

**A tighter contact tolerance and more position iterations cannot remove the original 30/60 Hz initial-impact failures.** The source and frozen TOI payloads establish why. They can address a different mechanism—the resting/settling residual—but are not a complete quality configuration at the original single-step cadence.

**Proposed next choice:** retain the original default-settings references and failed physical results, and explicitly authorize a separate quality experiment with `linearTolerance = 1/4096 m`, at most eight position iterations, and fixed internal steps of `1/120 s` (4/2/1 steps per 30/60/120 Hz outer interval). This changes the stepping contract of the separate quality profile. It is **unapproved and unexecuted**, not a settings-only solution or a passing result. If the original one-world-step-per-interval contract must also hold for quality, this compound proposal must be rejected or deferred; the narrow tuning proposal alone is insufficient.

Supports [Design separately configured sleep/wake physical qualification](https://github.com/rubixhacker/dyn4k/issues/28) and the [investigation-only checkpoint](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-6172029308). The approved ceilings stay exactly 0 m approach, 1/100 m impact, 1/200 m initial/wake settling, 1/1000 m both rests. No default, algorithm, fixture, reference, phase or ceiling is changed by this report. [Numerical and migration acceptance](https://github.com/rubixhacker/dyn4k/issues/7) remains a human decision.

## What the pinned source actually does

All upstream links below pin dyn4j revision `058bf6d982a0fb89b54050f929f6ea9dae53b714` (6.0.0). The [previous physical audit](sleep-wake-penetration-acceptance.md) remains valid: 125,847 of 126,000 states fail. This investigation reads source and existing hash-guarded streams; it executes no physics.

1. [World.step](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/world/AbstractPhysicsWorld.java#L1225-L1321) first performs detection only if `updateRequired`, calls contact `preSolve`, saves previous transforms, and solves the constraint graph. It then calls contact/step `postSolve`, performs CCD, performs final collision detection, and calls step `end`. There is **no ordinary constraint solve after CCD or final detection in that step**.
2. [Island.solve](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/world/Island.java#L124-L211) integrates velocity, initializes/solves existing velocity constraints, integrates position, iterates existing position constraints, and processes sleep. With no contacts or joints, velocity constraint loops do not run and the [position solver immediately returns true](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/contact/SequentialImpulses.java#L539-L552).
3. [CCD selection](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/world/AbstractPhysicsWorld.java#L1400-L1514) already uses `ALL` for these dynamic-square/static-floor inputs. It skips existing contacts and resolves only one selected TOI per dynamic body. `BULLETS_ONLY` would exclude the non-bullet square; `NONE` disables this stage. Neither mode adds a constraint solve or an internal substep.
4. [ConservativeAdvancement](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/collision/continuous/ConservativeAdvancement.java#L95-L209) begins with a distance query, returns false when not separated or when distance is below its epsilon, and advances by `d / relativeClosingMotion`. It can return an empty zero-distance separation when an interpolated distance query reports intersection. Its distance epsilon is a stopping/search control, not a requested positive collision gap or penetration target.
5. [World TOI application](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/world/AbstractPhysicsWorld.java#L1700-L1726) interpolates the dynamic transform to TOI. **If reported separation is zero or negative it returns before invoking the TOI solver.** Otherwise [ForceCollisionTimeOfImpactSolver](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/contact/ForceCollisionTimeOfImpactSolver.java#L51-L102) translates bodies together by a mass-weighted correction based on `clamp(d + linearTolerance, 0, maximumLinearCorrection)`, intentionally creating contact. That solver changes position, not velocity. No remaining step time is simulated by this TOI path.

**Clarification of earlier prose:** the previous [phase report](sleep-wake-penetration-phases.md) correctly ordered ordinary solving, CCD, then final detection. It did not need reversal. “Contact creation is available to the next solve” must not imply CCD always creates contact or always invokes its correction solver: the zero-separation early return is decisive here. The source comment about making bodies collide “on the next time step” refers to the next ordinary solve; final detection itself is still in the current step. The [position solver's final comment](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/contact/SequentialImpulses.java#L628-L631) is also misleading: its executable condition is `minSeparation >= -3 * linearTolerance`, not the comment's “plus half” wording.

## Why narrow settings tuning cannot fix the initial failure

The selected streams' two actual TOI payload callbacks per Hz report **distance exactly zero**, at steps 1/3/5. Touchdown end poses have `s=0, c=1, ty=0.5`; velocities are respectively `−0.32666666666666666`, `−0.49`, `−0.4083333333333333` m/s. Final detection creates no contact at those touchdown samples. First contacts occur at 2/4/6 and first ordinary solves at 3/5/7. These are frozen observations, supported by [the event report](sleep-wake-penetration-phases.md) and newly reread payloads; manifest and source identities are preserved.

Changing **only** `linearTolerance` and position-iteration count leaves the path through these pre-contact steps unchanged: there are no contact position constraints to correct, the TOI correction that would read tolerance is skipped, and neither setting changes gravity integration, collision geometry or the detector. The next step begins touching, advances under unchanged velocity/gravity, and has no previously created constraint to stop it. Starting without separation also defeats a new CCD search; [GJK's overlap tests](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/collision/narrowphase/Gjk.java#L263-L292) are not a positive-margin contact generator.

Thus the **same** step-2 30 Hz penetration `196156783769915/9007199254740992 m` (approximately 21.7778 mm) and step-4 60 Hz penetration `196156783769915/18014398509481984 m` (approximately 10.8889 mm) remain above the 10 mm impact ceiling for that narrow configuration change. Their classifications cannot rescue them: the other approved positive ceilings are smaller. This is a source/data dependency argument for those unchanged prefixes, not a newly simulated candidate result or a theorem that every public setting is powerless. It assumes the same pinned executable, listeners, inputs, explicit `dt`, detector and stepping calls.

## Controls and their limits

| Public control | Source-supported effect and disposition |
|---|---|
| `linearTolerance` | Contact correction dead zone and `3L` solver stopping test; also used by nonzero-separation TOI correction. Reduce in the proposed separate profile; it cannot act on the zero-distance TOI branch. |
| Position iterations | Caps repeated correction of existing constraints. The island exits early when solved; increasing the cap does not force eight passes or create constraints sooner. |
| Velocity iterations, warm starting, warm-start distance | Affect solving/reusing existing contacts. Retain 6, enabled, 0.01 m; they do not supply a pre-contact normal impulse. |
| Baumgarte / maximum linear correction | Scale/cap existing contact positional correction. Retain 0.2 / 0.2 m; increasing them is not a remedy for an absent constraint. |
| Angular tolerance / maximum angular correction | Retain 2° / 8°; no joint is present. They are not an initial vertical-touchdown timing control. |
| Maximum translation / rotation | Retain 2 m / π/2 per step. [Translation clamping](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/AbstractPhysicsBody.java#L788-L827) rescales the actual velocity vector, not just measured penetration. A 5 mm cap at 30 Hz imposes a 0.15 m/s maximum integrated speed and can suppress the intended 1 m/s wake response. It is an explicit alternative workload change, not a free solver-quality improvement. |
| Sleep enable/thresholds/delay | Retain enabled, 0.01 m/s, 2°/s, 0.5 s. [Sleep](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/world/Island.java#L190-L211) requires low motion and a solved-position flag; [setting rest](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/AbstractPhysicsBody.java#L924-L939) zeros velocities without restoring a nonpenetrating pose. Earlier artificial sleep would change the test; disabling sleep removes required coverage. |
| CCD mode | Retain `ALL`; it is already the broadest mode relevant here. |
| `stepFrequency` | Retain its default metadata value. [Explicit `step(1,dt)`](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/world/AbstractPhysicsWorld.java#L311-L332) uses supplied `dt`, not this setting. Changing the setting alone does not substep these captures. |

The public defaults and setters are in [Settings](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/Settings.java#L35-L180), with [iteration setters](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/Settings.java#L527-L568), [tolerance setter](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/Settings.java#L651-L665) and [remaining controls](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/Settings.java#L673-L824). `ConservativeAdvancement` separately exposes [epsilon/iteration controls](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/collision/continuous/ConservativeAdvancement.java#L232-L275); these are not `Settings` and provide no documented “positive TOI target gap” control. Detector/solver replacement or changed collision semantics would require a different investigation and approval.

## One bounded candidate, not a tuning sweep

**Proposed contact settings:** `setLinearTolerance(1.0 / 4096.0)` and `setPositionConstraintSolverIterations(8)`; all other settings, algorithms and body/fixture properties remain as captured in the original selected input records. These two setter arguments are valid in the pinned implementation.

The tolerance is the largest power-of-two fraction no greater than one quarter of the independent 1 mm rest requirement: exactly 0.000244140625 m. The solver's `3L` threshold is then exactly 0.000732421875 m, below 1 mm. This allocates space under the quality requirement without deriving a value from observed maxima. **It is not a geometric error bound:** the solver measures contact separation estimates before corrections, not deepest exact square vertices. The eight-iteration cap is a predeclared fourfold increase over default two to allow more correction attempts while keeping the experiment bounded; it is a resource choice, not a convergence proof. Retain Baumgarte and correction limits to avoid simultaneous aggressiveness changes. No automatic fallback to 16 iterations or another tolerance is permitted.

**Proposed stepping, requiring a separate live choice:** one constant internal `h = 1.0/120.0` for all runs, grouped as follows. This uses the finest already selected nominal cadence consistently, without an adaptive or depth-triggered step rule; smaller integration increments address the time available for pre-contact drift. It is a hypothesis to test, not a guarantee inferred from the old 120 Hz result.

| Outer cadence | Explicit world calls per outer interval | Inner states in 600 s | Outer endpoint observations |
|---|---|---:|---:|
| 30 Hz | 4 × `world.step(1, 1.0/120.0)` | 72,000 | 18,000 |
| 60 Hz | 2 × `world.step(1, 1.0/120.0)` | 72,000 | 36,000 |
| 120 Hz | 1 × `world.step(1, 1.0/120.0)` | 72,000 | 72,000 |

`step(n,elapsedTime)` treats elapsed time as **per world step**, not time divided across `n`; never pass the outer `dt` with `n>1`. Record outer cadence/duration and internal `dt` as separate metadata. Outer cadence does not remain the physics timestep at 30/60 Hz. Preserve the floor/square geometry, initial pose, gravity, density, friction, restitution, damping and 600 s duration. Apply the same `(1,0)` center impulse immediately before the first inner step of outer frame `300*Hz+1`, i.e. inner step 36,001 for every run, after 36,000 internal steps. Record the before/after action snapshots and sleep prerequisite over simulated seconds 299–300. No extra impulses or outer-boundary state mutations.

Because each candidate uses the same internal timestep and action index, these are three grouping/sampling journeys, not three distinct integration-timestep qualifications. This profile would not establish 30/60 Hz single-step physical quality. Original single-step behavioral/parity references remain separately required and physically failed.

## Proposed execution and phase governance

No execution is authorized here. If approved, freeze the complete profile and protocol before any run. Use the same pinned JAR (`204ca8dd55626ad3727b82dacb37df1800c5eff0d6bb6e782b6e5af5162b2b3e`), fixture source lineage and recorder contract, with a new caller/recorder revision for internal sampling and declared settings, independently reviewed during execution of the approved protocol. This implementation review need not create another human approval checkpoint; the later live review of candidate identities and exact phase indices remains required. Hash source, binary, runtime, complete input/configuration records, raw streams and phase manifests; assign new identities distinct from every original reference.

Run **one compound candidate**, two fresh captures at each outer cadence: six 600 s journeys, 432,000 internal end-state records total. Repeats check reproducibility; they are not parameter trials. Capture every inner end-state and callback, plus mark every outer endpoint. A logger only invoked after an outer call is insufficient. Stop further candidate work on capture/provenance/finite-data faults; retain full physical failures without tuning. A physical failure in a valid capture should remain recorded while that predeclared capture completes, so later rest/wake evidence is not lost.

Predeclare the *proposed* baseline phase rule before capture: approach before the first actual TOI payload; impact from that inner step through the first subsequent ordinary solved-contact step; initial settling through the step before first natural sleep; rest until the fixed action; wake settling until return to natural sleep; rest thereafter. Require actual event/sleep evidence, a sleeping 299–300 s prerequisite, immediate wake, a later natural return to sleep and nonempty rest coverage. Missing/ambiguous events or extra contact-loss/reimpact episodes make this proposed schedule inapplicable pending human review; do not silently invent a new allowance.

After capturing, derive phase indices from events **without using penetration values to choose boundaries**, then obtain live review of the new exact inclusive indices and reference identities before physical acceptance evaluation. The original schedules and their failures remain untouched. Freeze the reviewed candidate schedule for every later matching-config port; never classify a port by its own sleep/contact timing. Each outer endpoint inherits the phase of its corresponding inner index; every inner sample is also checked, so an outer pass cannot hide an internal failure. The limits themselves stay unchanged.

Use exact rational or independently outward-certified four-vertex geometry, including finite floor span and pose guards, exact rational ceilings and all-sample failure output. The earlier audit's geometry method can be reused only after adapting and verifying input identities and the new fixed schedule; its existing hash guards and original indices deliberately reject this new profile. Require independent arithmetic/geometry and boundary tests for that adaptation. Verify complete event/finite/sample counts, action invariants and both sleep/rest intervals separately from penetration. Any all-state physical failure leaves the candidate unqualified; it does not authorize moving a phase or relaxing a ceiling.

A successful experiment would establish only this declared baseline configuration's measured physical behaviour and reproducibility on the captured runtime. It would not qualify other timesteps, unchanged single-step quality, a dyn4k port, numerical parity, all target runtimes, performance or release support. Matching-config baseline-to-port tolerances still need review; callback order/counts and sleep timing must use the new reviewed reference. The original default-settings parity lane remains intact. Performance must be measured per simulated second and per outer interval as well as per internal step; more steps and a higher iteration cap incur real cost. Existing independent performance gates are not waived.

## Remaining human choice

Approve or reject **the compound profile and six-capture protocol**, including changed internal stepping, exact candidate settings and two-stage phase/reference review. The recommended route is this explicitly separate profile. If changing integration cadence is unacceptable, retain the unresolved physical-quality gap and choose further source research on a different declared workload/control policy; a motion cap, changed initial conditions or algorithm substitution is not implicitly authorized. A tolerance-only rest diagnostic could be requested separately, but cannot settle the complete physical gate and is not included in this experiment. No new run, reference acceptance or changed quality requirement follows automatically from completing this research.

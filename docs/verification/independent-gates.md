# Independent gate archive verifier

Run `independent_gates.py` for one exact Git commit and one approved runtime lane. It reads the reviewed manifest from revision `2f5eb2d40df2d8549bb45f137e9f6b2c258e6ada`. Its canonical JSON SHA-256 is `9aa2f50dd3c38129a70f4ed042f2b7ae5a90d4234def40d70520aad13f36b3fc`. The manifest contains 2,526 cases: 2,523 portable and three JVM-only. It retains 21 targets, 28 target/runtime families, and 112 lanes.

The approval covers source inventory and case selection. It does not pass a runtime lane or gate. Missing or changed source, map, pair, case, revision, or manifest bytes remain rejected.

```sh
python3 tools/qualification/independent_gates.py \
  --candidate-sha "$CANDIDATE_SHA" \
  --lane 'jvm:Java:minimum:no-optimize' \
  --expected-artifacts /audit/jvm-target-hashes.json \
  --expected-all-target-artifacts /audit/all-21-target-hashes.json \
  --expected-producer-scopes /audit/producer-scopes.json \
  --expected-archive-digests /audit/archive-digests.json \
  --expected-runtime-identity 'selected runner identity' \
  --archive staged-consumer=/archives/consumer \
  --archive publication-contract=/archives/publication
```

The selected hash file maps `dyn4k-core` and `dyn4k` to audited binary SHA-256 values. The all-target file maps every approved target to those two binary hashes. The publication gate requires all 21 targets. The archive digest file maps gate names to `archive_digest(archive_path)` values. An independent archive auditor must record those digests before evaluation. Values copied from a producer receipt do not establish independent provenance. The evaluator cannot authenticate the auditor; the adapter must retain the independent audit record.

The producer scope file maps numerical, Java corpus, migration, performance, and review gates to independent evidence scopes. Each scope names its exact candidate and producing runtime. The candidate SHA must equal the selected commit.

Java scopes pin both JVM JARs and `full-ci/lane-manifest.json`. Migration scopes pin the producing JVM core JAR and `evidence/summary.json`. Pilot performance scopes pin both JVM JARs and `evidence/candidate-identity-at-pilot.json`. Sustained performance scopes instead pin `evidence/archive.json`, the reviewed verifier SHA-256, and the approved policy SHA-256. Review scopes use target `source`, no artifact hashes, and separate `standards.json` and `spec.json` hashes.

The verifier rehashes each named manifest. It checks source identity and route-specific counts. Each archive receipt repeats its scope in `producer_scope`. Native KLIB hashes never replace a global JVM producer's JAR hashes. The adapter must supply each scope audit independently of the producer receipt.

The importable `evaluate` function verifies one selected lane and its four global gates. It accepts the approved manifest and independent archive, artifact, runtime, and producer-scope audits. `evaluate_assembly` verifies every approved lane from a 112-entry input map. Its digest binds each lane result, selected case count, and `qualify_adapter` record. The adapter emits complete case results only after a full selected-suite consumer route and every required gate pass. `qualify.py record` ingests the signed adapter result and rechecks its candidate and artifact audits. The CLI exits zero only when every required result passes.

For low-level gate evaluation, pass `--assembly /audit/lanes.json` instead of `--lane` and repeated `--archive` arguments. The JSON object has one key per approved lane ID. Each lane maps to `archives`, `expected_artifact_hashes`, `expected_runtime_identity`, `expected_archive_digests`, and `expected_producer_scopes`. Archive values are paths. The evaluator reruns `evaluate` for all 112 lanes. It rejects missing lanes, wrong binary hashes, inconsistent global receipts, and unbound passing gates. A missing archive remains `NOT_RUN` in the assembled result. This gate result does not authenticate the supplied audit values.

## Assemble the qualification record

`independent_adapter.py assemble` writes one digest-bound qualification record for all 112 approved lanes. With no archive map, it evaluates every gate as `NOT_RUN` and exits with code 1:

```sh
python3 tools/qualification/independent_adapter.py assemble \
  --candidate-sha "$CANDIDATE_SHA" \
  --output /audit/independent-assembly.json
```

With raw archives, the command requires a complete 112-lane map and a detached, independently signed audit. Supply the public key and its separately trusted DER SHA-256 fingerprint. The candidate manifest and staged audit must bind the same source and all 21 target binaries.

```sh
python3 tools/qualification/independent_adapter.py assemble \
  --candidate-sha "$CANDIDATE_SHA" \
  --archive-map /audit/archive-map.json \
  --signed-audit /audit/independent-audit.json \
  --audit-signature /audit/independent-audit.sig \
  --trusted-public-key /trust/auditor-public.pem \
  --trusted-key-sha256 "$AUDITOR_KEY_SHA256" \
  --candidate-manifest /audit/candidate-manifest.json \
  --staged-audit /audit/artifact-audit.json \
  --evidence /audit/lane-evidence.json \
  --output /audit/independent-assembly.json
```

The archive map uses the `record --independent-archives` schema. The signed audit uses the corresponding `record --independent-audit` schema. `--evidence` uses the `record --evidence` lane map and is optional while lanes remain unexecuted. A claimed green lane cannot pass without verified raw gate archives. An attempted invalid archive is `FAILED`; a missing archive is `NOT_RUN`. The output includes every selected case count, gate result, qualifier result, manifest digest, archive map digest, signed audit digest, and final result digest. The command verifies stable copies of the signed inputs. It never creates a signing key or signature.

The current qualification workflow produces bounded common, hosted, and full CI archives. Its central collection job inventories raw producer artifacts and retains failed routes. It does not assemble an exact-candidate 112-lane archive map, candidate manifest, staged audit, and external signature in one job. The full hosted external consumer executes foundation cases; its raw archive cannot satisfy the 2,523 or 2,526 selected-case consumer route. A separate auditor must supply the complete signed inputs and trusted key fingerprint. A producer must execute the complete selected suite through each staged external consumer before that gate can pass. Current-source numerical, physical, sustained, and review obligations remain separate.

## Common raw archive

Each archive contains `receipt.json` and every file listed in `receipt.files`. Each file entry has a safe relative path, SHA-256, and original nanosecond mtime. The extracted filesystem mtime must equal the recorded mtime and fall inside the process execution window. The auditor digest covers every extracted file's bytes, path, and filesystem mtime. The verifier rejects unlisted files, duplicate paths, traversal, symbolic links, changed bytes, changed mtimes, and wrong candidate or lane identities.

A passing receipt binds the exact candidate SHA and Git tree, the selected lane where applicable, and audited producer artifact and runtime identities. Its process record includes a command, integer exit code, start and finish times, and raw output paths where the route requires them. Consumer, provider, and publication routes require a recognized launcher, exact lane marker, and raw task outcome in process output. Gradle routes also require task and build outcome lines. Consumer and provider output includes SHA-256 lines for the raw XML, graph, and resolved binaries it produced. These records only become evidence after an independent archive digest and artifact audit bind their origin.

No archive yields `NOT_RUN`. A complete external unavailability observation yields `UNAVAILABLE` with its reason. A malformed attempted pass or a raw failure yields `FAILED`. A producer `PASSED` string cannot replace raw files or audited provenance.

# Numerical preflight for the full compatibility corpus

Use this package when the full port recorder can emit the frozen record stream.
It prepares references and checks for [Run the full compatibility corpus and unchanged migration applications](https://github.com/rubixhacker/dyn4k/issues/42). It does not qualify a port, target runtime, or release.

## Frozen inputs and decisions

[The catalog](../../tools/numerical/fixtures.json) has 14 trace members in four profiles. It records the dyn4j 6.0.0 source revision `058bf6d982a0fb89b54050f929f6ea9dae53b714`, JAR SHA-256 `204ca8dd55626ad3727b82dacb37df1800c5eff0d6bb6e782b6e5af5162b2b3e`, recorder source hashes, archive and member hashes, input and decompressed-stream hashes, actions, sample schedules, counts, units, limits, and approval links. The six configured captures bind the manifest SHA-256 `7efd60aa76cab10fdc27eb8e968a2868e854433cc4556e10257dbd290a63e554`. Repetition 1 at each outer cadence is the approved reference; repetition 2 is corroboration. The historic `PENDING` labels in the original research manifests predate the linked approvals and were not changed.

The catalog retains the [approved nominal rotation caps](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-6162049136) and [configured sleep/wake caps](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-6184664626) with zero relative allowance. Position and velocity vectors use separate x/y scalar checks. Orientation alone uses the shortest wrapped angle; `rotationIncrementSum` uses direct difference. Contact normal/tangent rules use directed angle, magnitude, and required unit-length checks. The signed impulse rules retain N s. The [selected configured TOI limits](https://github.com/rubixhacker/dyn4k/issues/7#issuecomment-6236428418) are fraction `1e-6`, separation distance and each point component `1e-4 m`, directed nonzero normal angle `1e-4 rad`, and normal magnitude and required unit-length deviation `1e-6`. All have zero relative allowance. Event identity, order, presence, and zero placeholders remain exact. Fixed-floor callback velocities are exact zero; signed zeros compare as zero. No rule widens a limit for a target or after a failure.

The default sleep/wake traces keep their failed [represented-geometry physical gate](https://github.com/rubixhacker/dyn4k/blob/b7af287c3581f402053511d9556d65e610d71a5e/docs/research/sleep-wake-penetration-acceptance.md): 125,847 failures among 126,000 end states. The configured baseline separately passed 432,000 internal states and 252,000 endpoint mappings under its [approved physical ceilings](https://github.com/rubixhacker/dyn4k/blob/164dc39eb086ac202fdffa8a493915c216bc1be0/docs/research/sleep-wake-quality-acceptance.md). The endpoint rows are copies, not extra time steps. The four Weld/Pulley members remain parity references and diagnostics. Their physical residual gate is **UNPASSED** because no physical bound was approved.

The separate [Weld/Pulley physical declaration](../../tools/numerical/weld-pulley-physical-declaration.json) selects an application requirement **before its new baseline run**. At 60 Hz for 36,000 steps per case, steps 1–60 are excitation and steps 61–36,000 are the long run. A spring-enabled Weld with equal limits between a fixed member and a moving 1 m member must keep its world anchors within 0.01 m and its relative angle within one degree at each completed step. A taut 2 m, ratio-one pulley must keep the sum of its two geometric segments within 0.01 m of the initial rope length, including both extension and compression. Both cases start with a declared velocity; Weld also has a queued off-centre force before step 1. Neither case has a later mutation. These limits express the allowed play of this application; they are independent of the solver stopping criteria and old observed maxima. The four older references and their 39 over-tolerance enabled-pulley samples remain separate. The new baseline result will be reported after execution.

## Commands and result meanings

Use Python 3.11 or later. Supply an extracted member from its hash-checked release archive. For example:

```sh
python3 -m unittest discover -s tools/numerical -p 'test_*.py' -v
python3 tools/numerical/compare.py audit-reference --fixture configured-30-r1 --reference /path/to/Q-sleep-wake-outer30-repeat1-0.jsonl.gz
python3 tools/numerical/physical.py --fixture configured-30-r1 --reference /path/to/Q-sleep-wake-outer30-repeat1-0.jsonl.gz
python3 tools/numerical/replay_approved.py default-exact --package /path/to/dyn4k-sleep-evidence --output /tmp/default-exact.json
python3 tools/numerical/replay_approved.py configured-exact --package /path/to/dyn4k-quality-candidates --archive /path/to/dyn4j-sleep-wake-quality-20261014.tar.gz --output /tmp/configured-exact.json
python3 tools/numerical/inventory.py --fixture configured-30-r1 --reference /path/to/Q-sleep-wake-outer30-repeat1-0.jsonl.gz --legacy-paths tools/numerical/legacy-unbounded-configured-30-r1.json
```

`audit-reference` verifies the exact gzip member, decompressed stream, input header, record kinds and counts, finite numbers, contiguous states, event order, and configured endpoint copies. Its `PASSED` result is **frozen baseline only**. `physical.py` first makes that audit, then measures exact rational depth from stored binary64 transform coefficients against each phase ceiling. It returns `PHYSICAL_PASSED`, `PHYSICAL_FAILED` (exit 2), or `INVALID` (exit 1). It does not execute physics.

The future port recorder must preserve every record kind, step, event order, callback method, payload structure, body/contact identity, and matched contact-point order. The candidate trace may be JSONL or gzip JSONL. Its receipt must contain:

```json
{
  "source_sha256": "<exact candidate source-tree digest>",
  "artifact_sha256": "<exact staged artifact digest>",
  "candidate_commit": "<exact 40-character candidate Git SHA>",
  "trace_sha256": "<candidate trace file SHA-256>",
  "reference_source_revision": "058bf6d982a0fb89b54050f929f6ea9dae53b714",
  "reference_artifact_sha256": "204ca8dd55626ad3727b82dacb37df1800c5eff0d6bb6e782b6e5af5162b2b3e",
  "reference_trace_sha256": "<catalog gzip member SHA-256>",
  "expected_counts": {"inputs": 1, "event": 935967, "state": 72000, "outer-endpoint": 18000, "instrumented-callback": 2, "action": 1},
  "executed_counts": {"inputs": 1, "event": 935967, "state": 72000, "outer-endpoint": 18000, "instrumented-callback": 2, "action": 1},
  "skipped": 0
}
```

The count example is for `configured-30-r1`. The candidate source digest and artifact digest must come from the exact candidate build. Invoke:

```sh
python3 tools/numerical/compare.py compare --fixture configured-30-r1 --reference /path/to/Q-sleep-wake-outer30-repeat1-0.jsonl.gz --candidate /path/to/port.jsonl.gz --receipt /path/to/receipt.json --expected-source SOURCE_SHA256 --expected-artifact ARTIFACT_SHA256 --expected-commit CANDIDATE_GIT_SHA
```

Exit 0 means `PASSED` for every declared record and selected numeric rule. Exit 1 means `FAILED` or `UNPASSED`; the JSON result distinguishes them. Missing or nonfinite values, changed hashes, wrong identities, empty/skipped/incomplete suites, missing fields, changed callback order, and exceeded limits fail. Every numeric path without a selected rule or proved formula is listed under `unpassed_channels` and forces `UNPASSED`, even when its values equal the baseline. The selected TOI and stored sine fields now have rules. A baseline self-comparison can establish comparator completeness only. Exact same-run relationships and configured candidate runtime math still need qualification in the parent task.

## Channel classification and formula assumptions

The [frozen legacy list](../../tools/numerical/legacy-unbounded-configured-30-r1.json) names the 127 numeric path templates previously reported by baseline self-comparison. `inventory.py` verifies the configured 30 Hz repetition-1 member hash, stream hash, counts, and the presence of every legacy path. It emits a reason and status for each path. An unclassified path makes the command fail. The baseline inventory classifies 46 templates under selected limits, 18 under source formulas including sine, 8 as exact matrix aliases, 39 as exact identities, and 16 as exact zeros. These are path templates, not executed sample counts. The [pinned recorder](https://github.com/rubixhacker/dyn4k/blob/a7718eb6380b8fc51179a953dff4f3f33949c801/docs/research/sleep-wake-quality-capture/Capture.java) records state, endpoint copies, and the two immediate wake snapshots.

The selected position, orientation, velocity, and accumulator limits apply to previous transforms, endpoint copies, and the matching fields inside wake snapshots. The previous transform is the earlier stored body transform. An endpoint is an exact copy of its inner state; it does not consume another time step. The matrix `getValues` array is an exact same-run alias of stored cosine, sine, and translation fields. Translation entries inherit `1e-4 m`; cosine and sine use the formula checks below. The pinned scene adds only an impulse. Its force, torque, and accumulated force/torque fields must be exactly zero. Rectangle, fixture, and mass values in callbacks must match their frozen input values exactly because this scene never mutates them. This exact requirement can reject a target whose initial runtime math differs; no target has qualified that requirement here.

The static getter identity rule includes source calculations. [Rectangle construction](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/geometry/Rectangle.java#L47-L83) stores radius from a vertex magnitude. [Polygon mass creation](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/geometry/Polygon.java#L565-L620) uses area and inertia sums. The callback reuses these unchanged objects; it does not recalculate a new radius or mass. The existing frozen `inputs.*` rule requires exact initial getter values, including any `sqrt`, division, or `atan2` result. A changed value fails this strict fixture; no cross-target error enclosure for those initial calculations is claimed. Negative tests alter the repeated radius and inertia values and require failure.

[The pinned body getters](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/AbstractPhysicsBody.java#L1059-L1101) calculate `getChangeInPosition` by subtracting previous translation from current translation. For each x/y component, the derived pair cap is `2e-4 m + e_reference + e_candidate`, where each `e` is the exact rational residual between the represented getter and the exact subtraction of its two represented source values. Each source translation must independently pass its `1e-4 m` cap. The comparator also requires the getter to equal the binary64 subtraction in its own run. This assumes round-to-nearest binary64 subtraction with no unrecorded transform mutation. A different getter value fails the same-run formula check; a pair beyond the derived cap fails the pair check.

The same pinned source computes `getChangeInOrientation` from the two stored public angles and angular-velocity-dependent wrap branches. Both angle sources must pass their `1e-4 rad` shortest-angle caps. The comparator requires the same branch, the exact binary64 source formula in each run, and a direct getter difference at most `2e-4 rad + 16 ulp(2*pi)`. The arithmetic term encloses the source's binary64 additions and subtractions when the branch and angle representation agree. The branch check fails closed near wrap or velocity-sign changes. It does not assume that `atan2`, sine, or cosine agree across targets; those target runtime paths need their own evidence.

The pinned [transform getter](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/geometry/Transform.java#L532-L537) returns signed `acos(cost)`. [Java 21 `Math.acos`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Math.html#acos(double)) requires error within one ulp. The comparator encloses the true cosine of each recorded angle with a rational Taylor remainder and allows two ulps of the returned angle around binade boundaries. It then requires `|cost_port-cost_reference| <= 1e-4 + e_reference + e_port`, where each `e` is that fixed two-ulp allowance plus the certified Taylor interval width. This is a formula-specific consequence of the selected orientation cap and a checkable runtime-math premise. A target that does not meet the premise fails; no target has yet been tested.

The same source uses only the **sign** of stored `sint` when it forms the public angle. The angle getter alone does not constrain sine magnitude. The delegated configured-profile decision adds an independent, dimensionless norm-quality condition for each stored pair: `|sqrt(cost^2+sint^2)-1| <= eta`, `eta = 1e-8`. This is an engineering requirement on both reference and candidate, with zero relative allowance. The comparator evaluates the equivalent squared inequalities on exact rationals made from the represented binary64 coefficients, so its own square root cannot change a boundary result. It also requires both coefficients within the source clamp `[-1,1]` and the source sign relation. This is separate from the nominal free-motion coefficient cap.

The selected `eta` has a fixed-operation rationale. The [pinned transform update](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/geometry/Transform.java#L101-L111) forms each coefficient with two binary64 products, one addition or subtraction, and a clamp that cannot increase component magnitude. The [pinned scene](https://github.com/rubixhacker/dyn4k/blob/a7718eb6380b8fc51179a953dff4f3f33949c801/docs/research/sleep-wake-quality-capture/SleepWakeQuality.java) has one dynamic rectangle, one fixed floor, no joints, 72,000 internal steps, and eight position iterations. [Position integration](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/AbstractPhysicsBody.java#L788-L827) adds one rotation per moving step. The [contact position solver](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/contact/SequentialImpulses.java#L580-L630) can add at most two point corrections per iteration for this one rectangle pair. The 33-rotation step envelope includes those 17 operations and 16 extra slots. A [TOI interpolation](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/geometry/Transform.java#L674-L713) resets coefficients from `Math.cos` and `Math.sin`; the [TOI solver](https://github.com/dyn4j/dyn4j/blob/058bf6d982a0fb89b54050f929f6ea9dae53b714/src/main/java/org/dyn4j/dynamics/contact/ForceCollisionTimeOfImpactSolver.java#L60-L105) translates rather than rotates them. Under round-to-nearest binary64, finite normal operands, and [Java `Math.sin`/`Math.cos` error within one ulp](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Math.html#sin(double)), each trigonometric coefficient has at most `2u` absolute error for magnitude at most one. Two products and one sum add at most `4u` absolute error per stored component before clamping. A `32u` norm-growth envelope per rotation covers those terms and their vector combination. For `N=72,000*33`, the geometric drift upper bound `N*32u/(1-N*32u)` is below `8.45e-9`, leaving margin under `eta`. The comparator checks this declared arithmetic envelope against the fixture. It tests each recorded pair against `eta`; it does not infer a pass from operation counts or silently enlarge `eta` if a runtime differs. A target must still establish these arithmetic and operation premises on its actual path.

For the component rule, let `epsilon_c = 2 ulp(4) + 2*4^40/40!`, covering the selected `acos` allowance and the 20-term rational cosine remainder on the certified angle domain `|angle| <= 4 rad`. The cosine check gives `|cost-cos(angle)| <= epsilon_c`. The norm rule and `|cost| <= 1` imply `|sint^2-sin^2(angle)| <= 2*eta+eta^2+2*epsilon_c`. With the exact source sign rule, each sine coefficient is within `delta = sqrt(2*eta+eta^2+2*epsilon_c)` of the true signed sine. The selected shortest angle limit and sine's unit Lipschitz bound then give `|sint_candidate-sint_reference| <= 1e-4 + 2*delta`, about `3.8284274e-4`, dimensionless, with zero relative allowance. The comparator uses an upward rational square-root enclosure, checks the component difference, and requires exact same-run aliases for matrix entries 1 and 3. It rejects over-limit norm/component values, invalid or nonfinite coefficients, and incorrect matrix aliases. A matching target `acos` and trig/error path remains unpassed for [Run the full compatibility corpus and unchanged migration applications](https://github.com/rubixhacker/dyn4k/issues/42).

## Evidence boundary

The [verified nominal baseline audit](https://github.com/rubixhacker/dyn4k/blob/f5053629d68dc134092434310c3d130ee1c0d9b5/docs/research/nominal-rotation-comparator.md) passed 144,000 rotation and 36,000 inherited-transform checks against its exact frozen member. That certified audit is retained as baseline evidence; this generic comparator does not replace its analytic enclosure. The [configured exact-consistency audit](https://github.com/rubixhacker/dyn4k/blob/44dd7cf05502fa4b5fdc3523e3271c3cba335de8/docs/research/sleep-wake-quality-exact-checks.md) passed on six frozen captures, including 5,615,802 events. It remains a separate same-run check, not a port result.

The package has no port candidate trajectory. [The parent corpus task](https://github.com/rubixhacker/dyn4k/issues/42) must connect a full recorder, rerun exact same-run checks and physical gates on the candidate, and qualify the selected sine norm, source-operation premises, and every other formula on each target/runtime/build lane. The default physical failure, Weld/Pulley physical gap, unchanged Java application journeys, and full corpus coverage remain open.

`replay_approved.py` restores the exact checker files from pinned Git commits into a temporary directory. It runs the default and configured same-run checkers above. With the exact nominal gzip member, `nominal-rotation --raw MEMBER --output NEW_DIRECTORY` runs the original certified rotation audit. A missing pinned Git object or mismatched checker hash stops the replay. These commands inspect frozen baseline bytes only.

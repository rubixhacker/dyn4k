# Full Ubuntu CI evidence

The Ubuntu job runs the complete common corpus and the full Java compatibility gate at the workflow commit. It also retains the existing staged publication, consumer, duplicate-provider, and bounded probe checks. The hosted macOS, Windows, and Safari jobs remain separate.

`qualification.yml` installs JDK 8 and JDK 21. It fetches dyn4j source revision `058bf6d982a0fb89b54050f929f6ea9dae53b714` into a declared temporary path and checks the revision before testing. The baseline verifier in `full_ci.py` independently downloads and checks the pinned 6.0.0 binary and source JARs, then runs the unchanged Java corpus. The compatibility gate records 2,385 case identities across its baseline, staged JVM, and staged Android host providers with Java 8 and 21 compilation and execution. It also checks source compatibility, added members, exception serialization, and World fixtures.

The complete common gate invokes all 12 available Ubuntu host tasks. The JVM groups require 2,515 source-derived identities. Each Linux, JS Node, Wasm JS Node, Wasm WASI Node, and Android host pair requires 2,512 identities. Its binding records the command, environment, source manifest, process window, raw XML, and produced artifact hashes at `GITHUB_SHA`. The separate compatibility result records the staged JVM and Android archive hashes at that SHA. The existing publication receipt and consumer probes cover the staged variants and duplicate-provider rejection.

The `full-common-<sha>` upload contains its binding, result, Gradle log, built artifacts, raw XML reports, and reviewed inputs. It also contains an archive index, a tar archive, and SHA-256. CI checks the tar bytes, extracts the archive, and runs `full_corpus.py verify-archive` on the extracted files before upload. The public archive verifier needs a candidate checkout at the archive SHA and a dyn4j checkout at the pinned revision. It reads bound artifacts, reports, and the Gradle log from the relocated archive. It checks their hashes and the complete file inventory against the binding and candidate sources. The `full-ci-<sha>` upload contains the sealed compatibility directory as a tar archive and SHA-256; CI verifies its extracted archive. An upload can contain failed diagnostic evidence; only a passing verifier result is a gate pass. A failed step remains failed even though later archive steps run.

These Ubuntu checks do not mark any complete-port support lane passed. The 112-lane matrix remains `NOT_RUN` until its independent gate archives verify at the same source and artifact identities. Hosted runners and physical devices need their own current evidence.

# Portable numerical consumer

The standalone consumer in `tools/numerical/portable` runs common Kotlin engine calls through staged `dyn4k-core` Maven publications. Its Gradle build does not include project source modules or the Java recorder. Run it from a clean commit. The runner freshly builds and hashes the metadata, JVM, Android, Linux x64, JS, Wasm JS, and Wasm WASI publications before any host task executes.

The clean-source check rejects tracked edits, untracked files, and ignored files outside named generated output roots. This includes source placed under an ignored `build` directory inside `src`. Only root-anchored Gradle output directories are excluded from that ignored-file check.

```sh
ANDROID_HOME="$HOME/Android/Sdk" python3 tools/numerical/portable/run.py \
  --prospective-baseline /var/tmp/dyn4k-portable-baseline-evidence \
  --output /var/tmp/dyn4k-portable-numerical-evidence
```

The runner has seven host routes: JVM 21, JVM 8, Android host, Linux x64, Node JS, Node Wasm JS, and Node Wasm WASI. The JVM 8 route uses `/tmp/dyn4k-tools/jdk8`. Android host uses a JVM and does not qualify an Android device. The publication log and manifest bind staged artifacts to the clean source revision.

The focused JVM operation route runs only `joint-Wheel-active` from `ProspectiveArithmeticTest.captureWheelActive`. From a clean commit, use `capture_actual.py --method captureWheelActive --reference-case <catalog-pinned Wheel case JSONL> --output <new home-backed directory>`. It stages the source and JVM artifact. The receipt retains JUnit XML, process logs, worker classpath and class loads, runtime binary, source archive, and case trace. It also hashes the per-thread kernel write traces. The verifier follows the executed worker's clone tree and compares all recorded output lines with the XML. The independent rotation oracle checks each recorded binary64 operation.

For this exact Wheel fixture, the adapter requires three calls per step in source order: `b1 integrate`, `b0 joint`, then `b1 joint`. This check includes zero-angle calls. The adapter also enforces a source-derived upper bound on rotations per body and the recorded transform chain. The kernel write witness links the XML lines to the executed worker process. The focused assessment leaves qualification `UNPASSED` while other target premises and cases remain unproved. It does not activate conditional U(N) for the 41 rotation failures or the 318 prospective cases.

The runner reruns 15 matrix methods separately to retain each raw JUnit report and compiler-input proof. It then assembles one ordered JSONL trace and case inventory. Each completed lane retains method logs and XML, the whole trace, case slices, a receipt, and a result. The verifier checks each method's process, runtime version, executed payload, and staged dependency. JVM receipts bind provider class bytes. The Java 8 process trace also requires the test worker to open the staged JAR. Node and native receipts bind compiler inputs and executed bundles or binaries. Missing process or dependency proof fails the receipt. Unexecuted lanes get `NOT_RUN` or `UNAVAILABLE` receipts with zero cases and unpassed qualification. Android device and Android Native x64 remain `NOT_RUN` in this consumer.

## Recorded contract

The declaration in `cases.py` is the expected case set. The suite records every inner step, ordered step, contact, and time-of-impact callbacks, before-step actions, and configured outer endpoint copies. Endpoint copies do not advance the step or event history. Each state records body transforms, prior transforms, velocity, force, torque, rest state, energy, momentum, joint reactions, and fixed-origin position. Geometry cases also record direct SAT and GJK observations. Nonfinite values appear as tagged raw values; receipt inspection rejects them outside the known Angle physical failure. Floating-point comparison uses binary64 bits, including the sign of zero, before any tolerance decision.

The six families cover geometry and collision boundaries; motion, forces, damping, and restitution; and default and configured contact, friction, sleep, and wake. They also cover joints, CCD, and a 600-second free-motion invariant scene. Joint cases include ten types, initial and active modes, 34 boolean controls, 86 numeric values, and 12 limit cases. Configured sleep/wake uses 120 Hz inner steps and 4/2/1 outer endpoint groups. Its six cases include two repetitions at each outer rate.

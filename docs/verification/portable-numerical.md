# Portable numerical consumer

The standalone consumer in `tools/numerical/portable` runs common Kotlin engine calls through staged `dyn4k-core` Maven publications. Its Gradle build does not include project source modules or the Java recorder. Run it from a clean commit. The runner freshly builds and hashes the metadata, JVM, Android, Linux x64, JS, Wasm JS, and Wasm WASI publications before any host task executes.

```sh
ANDROID_HOME="$HOME/Android/Sdk" python3 tools/numerical/portable/run.py \
  --output /var/tmp/dyn4k-portable-numerical-evidence
```

The runner executes JVM on Java 21 and Java 8, Android host, Linux x64, Node JS, Node Wasm JS, and Node Wasm WASI test tasks. The Java 8 lane selects the Gradle test launcher from `/tmp/dyn4k-tools/jdk8`; its receipt hashes the process Gradle actually launched. Android host execution uses a JVM. It does not qualify an Android device. The publication log and manifest bind the staged artifacts to the clean source revision. Each completed lane retains its Gradle log, raw XML, whole JSONL trace, per-case JSONL traces, SHA-256 receipt, and result. Every lane without execution gets a `NOT_RUN` or `UNAVAILABLE` receipt with zero executed cases and an unpassed qualification status.

## Recorded contract

The declaration in `cases.py` is the expected case set. The suite records every inner step, ordered step, contact, and time-of-impact callbacks, before-step actions, and configured outer endpoint copies. Endpoint copies do not advance the step or event history. Each state records body transforms, prior transforms, velocity, force, torque, rest state, energy, momentum, joint reactions, and fixed-origin position. Geometry cases also record direct SAT and GJK observations. Nonfinite values appear as tagged raw values; receipt inspection rejects them. Floating-point comparison uses binary64 bits, including the sign of zero, before any tolerance decision.

The six families are geometry/collision boundaries across scales and offsets; free motion, forces, damping, and restitution; default and separately configured contact, friction, sleep, and wake; all ten joint types with initial and active modes, false/true/timed toggles for 34 applicable boolean controls, 86 numeric value cases, and 12 equal or range limit cases; circle and pentagon CCD at 30, 60, and 120 Hz; and a 600-second free-motion invariant scene. A separate 600-step Angle ratio `-1` case retains the reproduced baseline nonfinite failure while allowing other test methods to run. Default sleep/wake uses its own 30/60/120 Hz step. Configured sleep/wake uses 120 Hz inner steps and separate 4/2/1 outer endpoint groups. Its six cases include both repetitions at each outer rate.

The receipt validator rejects missing or duplicate cases, missing steps, lost callbacks, altered action steps, reordered events, changed input, changed signed zero, missing endpoints, nonfinite values, stale artifacts, and an empty suite. The receipt binds the exact Git archive hash, commit, staged metadata and target artifact hashes, runtime identity, trace hash, and expected and executed counts.

The Pulley preparation is a continuation: its second segment records absolute steps 2 and 3 after the first segment's step 1. The receipt checks that starting step and rejects a reset or gap. Frozen projections are required on each mapped input, step, callback, action, and configured endpoint. The receipt also checks the fixed frozen case ID, origin, scale and configured grouping against the declared case, so a changed projected identity cannot pass while the portable input stays unchanged.

`reference_diagnostic.py` first checks the frozen gzip and input hashes and attempts a streamed comparison of the raw portable records, including an explicit signed-zero check. It reports the raw transport schema differences. It then compares the complete typed frozen projection with the approved comparator, and separately records overlapping body channels and exact-value differences. The projected comparison fails on missing or reordered records, signed zero, unapproved channels, or failed approved limits.

For the 14 frozen case mappings, the common recorder also captures typed projections of the complete frozen input header, baseline settings, world configuration, the initial body/fixture/joint state, every later body/joint state, ordered StepListener, collision, contact and TOI payloads, actions, instrumented callbacks, and configured outer endpoints. It reads engine values from the staged publication and rejects an unexpected algorithm, shape, filter, or joint type. The diagnostic streams the complete projected sequence through the approved comparator, including signed zero, and separately reports exact event and auxiliary-record differences. On the pre-integration Android host run, all 14 input projections had the frozen structure; value differences remained in the old `pow` TOI epsilon, World broadphase tracking and one Weld perimeter ratio, and Pulley main initial state. The nominal Java 8 run projected all 108,001 StepListener records exactly. A focused JVM run projected all 1,801 Weld and all eight first Pulley preparation events exactly; the second preparation and Pulley main still differed numerically. The pre-integration configured 120 Hz run recorded 935,991 projected events against 935,967 frozen events, with 467,938 exact events; the 24 surplus callbacks and later value differences remain failed. These projections are embedded in the portable trace and reproducible from its source revision. Any projected mismatch or channel without an approved rule remains unpassed; the raw envelope's additional recorder fields are reported separately.

The nominal force, torque, accumulated force and accumulated torque fields are positive zero in all 36,000 frozen samples and in the corresponding Java 8 projection: 432,000 exact-zero values across both traces. The nominal fixture now contains the approved exact-zero rules for these four channels. The diagnostic checks positive zero on both sides, rejects nonzero and negative-zero controls, and fails the projected verdict if this rule fails. It applies no new tolerance. Final integrated candidate execution remains pending.

The configured 120 Hz JVM wake sample also projected its before-wake state, impulse action, and after-wake state as three exact auxiliary records against the pinned reference. Its other old-source event differences remain failed.

The physical diagnostic reuses the approved represented-geometry depth and phase schedule for default and configured sleep/wake cases. It reports all nine case counts and failed steps separately; default failures remain failures. The 36,000-step free-motion invariant is checked against its analytic limits. These diagnostics do not replace input, event, or complete-channel parity.

The runner invokes that diagnostic for every frozen reference found in `--reference-dir`, using `/tmp/dyn4k-configured-control/baseline-trace` by default. Each host gets `frozen-comparison.json` with explicit unavailable references. A missing reference, nonmatching schema, or failed approved channel never becomes a parity pass.
Independent frozen case comparisons run in four bounded worker processes after each host test. The result list remains in fixture order, and each worker reads only the retained per-case trace and its pinned reference.

## Acceptance boundary

The pinned baseline is dyn4j 6.0.0 at source revision `058bf6d982a0fb89b54050f929f6ea9dae53b714` and binary SHA-256 `204ca8dd55626ad3727b82dacb37df1800c5eff0d6bb6e782b6e5af5162b2b3e`. The approved 14 reference traces use the frozen Java schema and exact input headers. The portable recorder keeps additional receipt fields around a typed frozen projection. A successful portable receipt proves that its declared cases ran and were bound to staged artifacts; numerical parity requires the complete projected comparison to pass every approved rule, and physical qualification remains separate. Any unmatched projected input, event, state, case, or runtime remains unpassed.

The configured control in `/tmp/dyn4k-configured-control/result.md` is a mixed diagnostic. Its 1,025,970 matching runtime records do not qualify one coherent candidate artifact. The previous `pow` versus pinned `cbrt` default TOI input difference must be checked on the final merged source. The Angle ratio `-1` case produced `-Infinity` at step 171 with the pinned baseline alone, as recorded in `/tmp/dyn4k-angle-baseline-probe/result.json`. It remains a failed physical case and is ineligible as a finite numerical reference. Neither observation permits a trace rewrite or a wider acceptance limit.

# Full staged KLIB consumer

The external project at `consumers/qualification/portable/full-klib` compiles the approved portable test sources against separately published core and facade Maven KLIBs. It also compiles the unchanged Native or JS test `actual` source required by the common tests. It has no engine project dependency. The core and facade tests run in separate modules. Both modules resolve both publications.

The local producer accepts eight approved lane IDs: Linux x64 at minimum and current with `debug-g` and `optimized-opt`, and Node.js at minimum and current with `development` and `production`. The approved manifest selects the same 2,523 portable method IDs for each lane. The input files retain the manifest order. The Native XML and Node TAP use the runners' execution order, which differs from manifest order in the retained full archives. This code does not by itself qualify a lane. Other Native and JS/Wasm targets remain requirements.

For Linux x64, `debug-g` selects the effective `-g` compiler mode, links `debugTest`, and runs that binary through `linuxX64Test`; `optimized-opt` selects the effective `-opt` mode, links `releaseTest`, and makes `linuxX64Test` execute that release binary. For Node.js, the selected development or production executable compile task produces the matching `testDevelopmentExecutable` or `testProductionExecutable` bundle. Node runs the selected bundle and retains its TAP. The archive contains the Gradle debug log with KGP's actual JS compiler arguments or Kotlin/Native's actual compile and link arguments, the task provider options record, the executable bytes, and the raw XML or TAP. The verifier checks the invoked target, effective mode, output path, and both resolved publication paths against the selected lane.

Schema-2 captures use `--debug --max-workers=1 --no-parallel` in the exact Gradle command. The verifier checks that command and the logged `[QUIET]` or `[LIFECYCLE]` qualification markers. It also requires the selected tasks' `[LIFECYCLE]` task rows and `[DEBUG]` execution rows.

The minimum Node.js runner must execute Node.js 22.0.0. The minimum Linux x64 runner must report kernel 4.9.156 and glibc 2.19. The producer rejects a newer runner for a minimum lane with an explicit unavailable reason. Current Linux x64 lanes require a Linux x64 host at or above the approved floor. Current Node.js lanes require Node.js at or above 22.0.0 on the selected host OS. The exact minimum profile cannot count as current. Each run records the observed kernel, glibc, Node version, executable hashes, and JDK identity. The independent caller supplies the expected runtime identity and toolchain during replay. A current run cannot be relabeled as minimum by changing the receipt.

The Node.js lane can run on another host OS. Its host identity and Node executable still need an independent audit. Linux kernel and glibc floors apply to the Linux x64 lane.

Use `tools/qualification/full_klib_consumer.py run` with a clean exact-source checkout, a staged Maven repository, independent core and facade KLIB SHA-256 values, pinned Gradle 9.5.0, JDK 21, and a selected Node executable. Set `JAVA_HOME`, `GRADLE_USER_HOME`, and `TMPDIR` explicitly. Put `--output` outside the source checkout on durable storage. The producer refuses an occupied output directory.

The Native compiler receives the Gradle-resolved cached core or facade KLIB as `-friend-modules`. The JS test compile and selected executable link task receive the resolved KLIB as `-Xfriend-modules`. Each resolved file must match the staged KLIB bytes. Native retains the original Gradle XML. Node uses its built-in test runner and retains the original TAP. The capture step derives normalized XML IDs only from those original method rows. It rejects missing, extra, duplicate, failed, or skipped methods.

Transport the complete raw directory or a tar that preserves file mtimes. The auditor calculates `independent_gates.archive_digest` from the transported directory. The auditor also selects the two binary hashes, runtime identity, and trusted toolchain JSON independently. Run `full_klib_consumer.py verify` from a separate clean checkout with the exact candidate test sources. Supply `--archive`, `--expected-archive-digest`, both binary hashes, `--runtime-identity`, and `--trusted-toolchain`.

Before it uses a transported test program, the verifier checks archive paths, symlinks, the supplied digest, and the complete file inventory. It compares original rows with normalized XML and checks both provider graphs and test programs. It then calls the independent staged-consumer gate.

For Node, `--replay-node` is required and must name the independently selected Node binary. The verifier rejects the producer checkout and requires a clean, unrelated source checkout. Before each replay, it compares the live preload bytes with the exact candidate's committed preload. It copies those bytes and the authenticated bundle to a temporary directory, checks the copies, and executes the copied preload and bundle. It checks the archive again at each replay boundary. The replay must reproduce the archived raw TAP method sequence and passing outcomes. A staged-consumer pass is one gate; it does not pass the full lane.

The trusted toolchain JSON must contain the exact `toolchain` fields selected by an auditor from the runner: JDK home, version and executable hash; Gradle version and executable hash; Node version and executable hash; Gradle user home; KGP version; and the Native compiler identity for a Native lane. A copy of the producer receipt is not an independent toolchain selection.

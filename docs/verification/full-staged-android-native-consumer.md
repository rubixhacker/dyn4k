# Full staged Android Native consumer

The producer in `tools/qualification/full_android_native_consumer.py` accepts the 16 approved Android Native lanes. Each lane selects one ABI, one API level, and one link mode. The approved manifest selects 2,465 core methods and 58 facade methods for each lane.

The external project at `consumers/qualification/portable/full-android-native` resolves both target KLIBs from the supplied staging repository by Maven coordinates. It compiles the unchanged common tests and the native actual source as test friend modules. It links the selected debug or release native test binaries. The producer checks their ELF ABI, pushes them over ADB port 5038, compares installed hashes, and executes both binaries on the selected guest. API 21 has no guest `sha256sum`, so that route pulls each installed binary and hashes the returned bytes. It retains the original GTEST event streams, normalized XML, source inventory, the test compile dependency graph, binaries, toolchain identity, guest properties, process IDs, and process logs in a lane archive. The graph records `${target}TestCompileKlibraries` only. It does not measure a separate runtime configuration.

Use the pinned JDK 21, Gradle 9.5.0, Kotlin 2.4.20, and AGP 9.3.1. Supply the staged core and facade KLIB SHA-256 values from an independent artifact audit. The source checkout must be clean at the selected candidate commit. Put the staging repository, work directory, archive, and `TMPDIR` outside the checkout. Invoke `run --help` for the complete producer arguments.

The public `verify` command requires independently supplied archive, staged KLIB, linked executable, runtime identity, and toolchain hashes. It checks the exact candidate sources and manifest, compile graph, original events, XML, linker command and output records, mode, ABI, API, and installed binary hashes. It validates the retained push, chmod, installed-hash or pull, and guest process records before live execution. It then pushes the archived executables to a matching live guest and executes the full selected set again. The generic staged-consumer gate runs only after that replay succeeds. The replay output directory is separate from the immutable archive.

The generic archive digest includes nanosecond file modification times. An ordinary copy that changes those times cannot replay, even if its bytes are identical. Use `pack --archive ... --archive-sha256 ... --package ...` to retain the raw bytes and exact file times in a transport package. Use `unpack --package ... --archive-sha256 ... --output ...` at the destination. Unpack checks each member hash, restores its recorded time, and authenticates the independent archive digest. Supply that digest again to `verify` on the unpacked directory. A copied archive qualifies only if its bytes and times preserve that digest.

The current route uses `emulator-5558` for API 37 x86_64 and `emulator-5560` for API 21 x86_64. Other ABI guests must be supplied by serial and must report the selected ABI and API. An x86_64 run does not satisfy an ARM or x86 lane. A linked binary without guest execution remains `NOT_RUN`. These staged consumer results do not settle numerical, physical, publication, or release gates.
